# SPIRIT Computer Use implementation

Target: Windows 11 x64 with an interactive, unlocked desktop. Public repository:
`scarrymany/spirit-computer-use`. Independent implementation, without bundled
OpenAI binaries, internal protocols, or runtime dependencies on Codex.

## Architecture

- Python package and stdio MCP server using the official MCP Python SDK 1.x.
- Spawned desktop worker isolates native capture/UI Automation hangs. The parent
  enforces deadlines. An interrupted write has an unknown outcome and is never retried.
- Windows Graphics Capture by HWND through windows-capture, not title matching.
- UI Automation through pywinauto, Win32 SendInput with foreground and hit testing.
- A separate non-activating, click-through overlay shows a purple window outline,
  cyan pointer halo, and action label. It never replaces the system cursor globally.
- All input coordinates are physical pixels relative to the captured window bounds.
  Snapshots carry identity and geometry. Stale snapshots are rejected.
- Named Windows mutex serializes desktop operations across independent MCP processes.
- Pause or Ctrl+Alt+Escape latches an emergency stop. Held keys/buttons are released.
- Shared skill and generated configuration snippets for Codex, Claude Code,
  OpenCode, Antigravity, and generic stdio MCP clients.

## Deliverables and checks

1. Validate window identities, coordinates, snapshot invalidation, error outcomes.
2. Implement capture, accessibility, input, launch and overlay lifecycle.
3. Expose discoverable typed MCP tools and CLI diagnostics/configuration generation.
4. Exercise real input in a disposable test window and verify its resulting text,
   clicks, drag and scroll events. Verify screenshots and the overlay visually.
5. Test the actual MCP initialize/list/call exchange through stdio.
6. Build/install the wheel; validate the skill and integration configurations.
7. Publish code, license, installation steps, compatibility matrix and actual
   validation results. Do not label untested agent applications as end-to-end tested.

## Scope limits

No remote control listener, service, account, model API key or administrator requirement.
No secure desktop/UAC control. Elevated apps need matching process integrity.
Minimized, protected and some hardware surfaces can refuse capture. UIA quality
depends on the target app. Separate popups may need their own selected HWND.
The terminal client's model must support images to reason over MCP screenshot blocks.
